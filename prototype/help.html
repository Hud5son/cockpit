Memory

Claude's notes to itself between sessions. Treated as an inbox: things are caught here, then moved to their proper home.

Where it lives

  • Vault/Tools/memory/, one fact per file, plus MEMORY.md, the one-line index every session loads.
  • Obsidian Sync carries it to the laptop like any other vault file.
  • Claude Code finds it through the autoMemoryDirectory setting in the vault's .claude/settings.local.json. That file never syncs, so each machine is set once.

How we treat it

  • Memory is a buffer, not a home. Anything with a proper home moves there: how Alex works to the global CLAUDE.md, vault rules to the vault CLAUDE.md, project facts to the node, traps to a Reference file.
  • What stays in memory is only what has no other home.
  • It stays switched on, because it is built into Claude Code and improves with it.
  • PROPOSED Session-close lists the memories written that session and offers a home for each. VOS row 31.

Don't

  • Don't keep project state in memory. It goes stale and the node already holds it.
  • Don't edit memory files through Obsidian's Properties panel. It rewrites the front matter.

Setting up a machine

python Tools/memory-setup.py

Run it from the vault. It sets the path and copies in any memories the machine held in the old place, never overwriting. Then start a fresh Claude session and ask it to "check the memory path": it should say Tools\memory.

Skills

Instructions Claude follows when asked, such as /session-open. A skill has no state. Work that runs on a cadence and leaves something behind is a workflow node, which may use a skill as its runbook.

Three places

KindLives inReaches the laptop byExamples
Vault skillsVault/Tools/skills/Obsidian Syncsession-open, session-close, meeting-notes, task-review
Global skills~/.claude/skills/SyncTrayzor, PC to laptoptdd, research, branded-deliverable, markdown-html-pdf
Plugin skillsManaged by the Claude appThe app itselfsuperpowers, anthropic-skills

Which goes where

  • Vault when it is about the vault or is a workflow's runbook, so it travels with the vault.
  • Global when it is general or used in ~/dev repos outside the vault.

How Claude finds vault skills

Claude Code looks in the vault's .claude/skills/. That folder is a junction, a signpost pointing at Tools/skills/, so the files live where Obsidian Sync can carry them. Each machine needs its own junction, made once.

cmd /c mklink /J "C:\Users\Alex\Documents\Vault\.claude\skills" "C:\Users\Alex\Documents\Vault\Tools\skills"

Editing

  • Vault skills: edit in Tools/skills/, on either machine.
  • Global skills: edit on the PC only. A laptop edit never reaches the PC.
  • Check it worked: the skill appears in the / dropdown of a fresh session.
